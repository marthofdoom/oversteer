# Coaching derivations

How every coaching aspect Oversteer needs is derived from telemetry, and
what each game provides towards it. Assetto Corsa Rally is the reference
game. The data lives in `data/telemetry/coaching/derivations.json`
(schema version 1). `oversteer/coaching_matrix.py` loads it and answers
per game:

```python
from oversteer import coaching_matrix as m
m.game_channels('acr')              # {channel: {'status', 'via', 'evidence', 'note', ...}}
m.available_aspects('acr')          # [(aspect, derivation used, missing optional channels)]
m.why_unavailable('acr', 'context.wet')   # ['puddles: needs channel puddle']
```

Unknown games and aspects give nothing (`{}`, `[]`, `None`), never an error.

## The three layers

1. **Channels**: every canonical quantity. That covers every `Sample` field
   of `oversteer/telemetry_formats.py`, in its units and conventions (car
   frame x forward, y left, z up; steer and yaw rate positive to the left;
   wheels FL, FR, RL, RR; clutch as a pressed fraction; `pos` in the world
   frame with y up). It also covers the derived basics (longitudinal and
   lateral g, body slip angle from the local velocity, curvature from yaw
   rate and speed, grade, driven-wheel slip, airborne), Oversteer's own
   clock, and the **rig** inputs Oversteer reads from the wheel whatever
   the game: pedals, handbrake axis, and shifter and paddle presses. A
   channel's `derive_from` lists the alternative inputs it can be computed
   from, including `static:<name>` game data.
2. **Games**: for each game, each channel's status:
   - `confirmed`: seen on a real capture, which is cited.
   - `decoded`: in code from published docs, unverified.
   - `derivable`: computed from other channels or game data.
   - `absent`.

   Each game also lists its static data from the game files, with a
   status of `shipped`, `in_game_files`, `planned` or `absent`. A channel
   a game doesn't list is resolved from `derive_from`. Otherwise it is
   absent.
3. **Aspects**: every coaching aspect. Each one has:
   - its derivations in order of preference. Each derivation gives a
     plain formula, the channels, static data and other aspects it
     requires, optional channels, and whether it is implemented or
     planned.
   - fallbacks and gates (discipline, surface, conditions).
   - outputs with units.
   - its validation status: `validated` on an ACR capture, `sim-tested`,
     or `untested`.
   - its implementation: the metric names and module, or `planned` with a
     ClickUp id.
   - its ACR coverage.

The first derivation whose requirements a game meets is the one used. A
derivation marked `sent_only` needs the game to send its channels, not
derive them. For example, a stage clock built from Oversteer's own clock
is not the game's clock.

## How ACR was checked

These pieces of evidence back the ACR statuses:

- **Channels.** marth's captures of 2026-09-25 cover Wales Afon Bidno -
  Severn, Greece Loutraki - Aghii Theodori and Alsace Forêt de Munster,
  with the Fabia RS Rally2 and the 208 Rally4. The capture of 2026-09-27
  covers Greece Elatia. The commits that decoded them are 0694e92
  (distance along the spline), b0534ef (signs), 4dc4c56 (finish and
  restarts) and 4a54a23 (position, from a graphics-page dump).
- **Aspects.** The seven ACR captures (copied, not read in place) were
  replayed through the live path on 2026-09-28. That gave 21 runs, 405
  corners and 500 shifts, and every metric the coach wrote was counted:
  - `shift.error` and `shift.in_band`: 234 flat-out upshifts.
  - `downshift.over_rev`: 224 downshifts.
  - `limiter.per_km`, `pedal.*`, `launch.t50`, `launch.bog`,
    `launch.stall` and `balance.gradient`: about 20 runs each.
  - `counter_steer`: 0.09 of cornering time.
  - `exit.low`: 378 exits.
  - `consistency.split_sd`: 1 value.
  - `corner.loss`: 4 values.

  ACR wrote no `launch.slip` or `shift.slip`, because the trace has no
  wheel speed. It wrote no `limiter.top` or `top.share`, because the run
  summary has no gear count. It wrote no `handbrake.per_km`, because ACR
  sends no handbrake. It wrote no H-pattern or double-tap metrics,
  because a replay has no rig presses and both cars are sequential.
- **Found along the way.** On marth's WRC Generations capture of the same
  day, counter-steer came out at 0.55 of cornering time, against 0.09 on
  ACR. The WRCG steer sign (or its yaw from positions) is probably
  inverted. Verify it before coaching counter-steer or balance there.

### Assetto Corsa Rally gaps

- No road edges: cutting, track use and line width cannot be judged, only compared with own runs (pos).
- No grip figure from the game (surfaceGrip 0): grip is measured (g-g envelope) or taken from the stage table surface.
- No stage clock: result times are Oversteer's own clock from the start to the last pace note.
- No handbrake channel: the rig handbrake axis has to stand in (not wired into the trace yet).
- No wheel speed or slip in the trace: tyreRadius is 0, wheelSlip is undecoded; wheel_rot x the learnt or game radius would give both (launch spin, exit spin, lock-ups).
- No suspension range (suspensionMaxTravel empty): bottoming needs a learnt bump-stop travel.
- No gear count in the packets: the top gear comes from the car data.
- No tyre loads or forces decoded (the bridge forwards wheelLoad, fx, fy): no per-wheel grip use.
- Position only since the 2026-09-27 bridge fix: older captures cannot place the car, so discipline by topology was unknown on them.
- The full pace-note list is in the game files but not shipped (86e3faftn).

## How to add a game

This fork is built for personal use. The games marth drives get this
treatment first: ACR, then WRC Generations, DiRT Rally 2.0, Forza Horizon
6 and BeamNG. Other games get it only if they get attention.

1. Decode it in `oversteer/telemetry_formats.py` into `Sample`, converting
   to the conventions above. If the format carries a quantity `Sample`
   lacks, add the field there and add a `sample` channel here. The test
   requires every `Sample` field to be catalogued.
2. Add a `games.<id>` entry. List the channels it sends as `decoded`, with
   notes for anything whose sign or unit is unverified. List every
   channel the game explicitly lacks as `absent` with the reason, so
   nothing is derived from it. Add its static data (stage table, car
   data) with its status, and its gaps.
3. Record a capture (`scripts/telemetry-capture.py`, or the Telemetry
   tab's recorder). Replay it with `scripts/telemetry-replay.py`. Promote
   each channel it shows right to `confirmed`, citing the capture.
4. Run `python3 -m oversteer.coaching_matrix --doc
   docs/coaching-derivations.md` and `pytest -q tests`. Check the game's
   `available_aspects()`, and check `why_unavailable()` for the ones it
   misses.

When the coach gains a metric, add its name to an aspect's
`implementation.metrics`. The test fails until every metric that
`oversteer/coach.py` and `oversteer/drive_log.py` write maps to an aspect.
